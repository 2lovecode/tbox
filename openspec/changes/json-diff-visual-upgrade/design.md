## Context

页面当前在纯 `textarea` 与对比后只读高亮之间切换；行路径由缩进和正则推断，嵌套结构容易失配。后端 `compare_json` 已返回稳定路径与原/新值，但前端未完整利用。

## Goals / Non-Goals

**Goals:** 宽屏布局；编辑时不降级成纯文本；稳定行差异映射；表格化明细。

**Non-Goals:** 不替换对比算法，不引入重量级编辑器依赖。

## Decisions

### 1. 焦点感知的代码编辑层

- **选择**：空闲时叠加只读 `pre` 提供 JSON 语法预览；聚焦后隐藏预览并切换到原生可见 `textarea`，diff 行颜色由输入框背景绘制。
- **理由**：编辑态不依赖覆盖层字符坐标，天然保证光标、选区和输入字符位置一致；背景条纹不参与文字布局。

### 2. 解析驱动的行路径映射

- **选择**：比较前先规范化格式化 JSON，同时基于解析对象遍历生成每一行的路径和类型；diff 结果按精确路径映射到行。
- **理由**：避免缩进/正则二次推导；容器和标量子项都可在同一行稳定标记。

### 3. 人工编辑优先

- **选择**：仅当输入已经是标准 `JSON.stringify(value, null, 2)` 格式时才用规范化行渲染；否则保留用户原始文本，仅做语法高亮。点击对比时统一格式化。
- **理由**：避免输入紧凑 JSON 时高亮层与实际文本宽度、光标位置不一致，保证粘贴后仍可连续人工编辑。

### 4. 差异明细表

- **选择**：将 `added`/`removed`/`modified` 归并为统一 `DiffRow`；表格提供类型过滤和值展示。
- **理由**：用户可先看统计，再按路径定位，减少在长 JSON 中检索的成本。

### 5. 操作栏与交互状态

- **选择**：清空放左侧弱化为破坏性操作，主操作对比靠右，中间显示输入/快捷键提示；无效输入禁用对比，无内容禁用清空。
- **理由**：主操作符合桌面表单的右下/右侧完成动线，避免破坏性操作和主要操作并排竞争注意力。
